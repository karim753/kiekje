1. Wat is Kiekje?

📸Kiekje is een app zoals Instagram. Je kunt foto's delen met je vrienden. Je kunt foto's leuk vinden, erop reageren, andere mensen volgen en berichtjes sturen.

🧸 Heel simpel Kiekje is een groot fotoboek dat iedereen samen maakt. Iedereen mag er foto's in plakken. En iedereen mag bij andermans foto een hartje tekenen of iets liefs schrijven.

De app is gemaakt met:

  • HTML — de stenen van het huis (wat er op het scherm staat)
  • CSS — de verf en het behang (kleuren, vormen, hoe het eruitziet)
  • JavaScript — de elektriciteit (knoppen die iets doen)
  • React — LEGO-blokjes voor de zoekpagina
  • PHP — de kok in de keuken (de server)
  • MySQL — de voorraadkast (de database, waar alles bewaard wordt)

5. De eetzaal: de frontend

De frontend is alles wat je ziet in de browser. Het is één pagina (index.html). Als je op een knop drukt, laadt de pagina niet opnieuw: het scherm verandert gewoon. Dat heet een single-page app.

Het geheim: het "geheugen" en de "tekenaar"

🧸 Heel simpel De app heeft een geheugen (state.js). Daarin staat: wie ben jij, op welke pagina ben je, welke foto's zijn er.
Dan is er een tekenaar (render()). Die kijkt in het geheugen en tekent het hele scherm.
Druk je op een knop? Dan verandert het geheugen, en de tekenaar tekent alles opnieuw. Net als een tekening die je gumt en opnieuw maakt.
  1. Geheugen (state.js): me = wie ben ik, tab = welke pagina, feedPosts = de foto's.
  2. Tekenen (render() in layout.js): maakt van het geheugen HTML.
  3. Knoppen aansluiten (events() in events.js): zegt tegen elke knop wat hij moet doen.
  4. Iemand klikt → de knop vraagt iets aan de server → het geheugen verandert → render() tekent opnieuw.

Voorbeeld: de ober (api.js)

// breng een bestelling naar de keuken en wacht op het antwoord
async function api(path, body) {
	const res = await fetch(API + path, { ... });   // ober loopt naar de keuken
	const data = await res.json();                   // ober komt terug met het eten
	if (res.status === 401) syncUser(null);          // "u bent geen klant meer" → naar inloggen
	if (data.error) throw new Error(data.error);     // iets mis? vertel het

}
🧸 Heel simpel fetch = de ober loopt naar de keuken. await = even wachten tot de ober terug is. 401 betekent: "Jij bent niet (meer) ingelogd."

Waarom esc()? (tegen stoute tekst)

Als iemand als reactie <script> typt, zou de browser dat kunnen uitvoeren als code. De functie esc() maakt er gewone letters van. Zo kan niemand stoute code in de app stoppen. Dit heet XSS voorkomen.

6. React: de zoekpagina van LEGO

De zoekpagina (frontend/js/search.js) is gebouwd met React.

🧸 Heel simpel React is een doos LEGO. Je bouwt kleine blokjes (componenten) en klikt ze in elkaar.
🧱 Avatar = het blokje met een profielfotootje
🧱 UserRow = een regeltje met één persoon (foto + naam)
🧱 SearchPage = de hele zoekpagina, gemaakt van al die blokjes
Elk blokje heeft een eigen geheugentje (useState): wat heb je getypt, wie is er gevonden.
function SearchPage() {
	const [query, setQuery] = useState('');       // geheugentje: wat is er getypt?
	const [results, setResults] = useState(null); // geheugentje: wie is er gevonden?

	useEffect(() => {                              // als "query" verandert...
		// ... wacht 250 ms en vraag dan de server: wie heet zo?
	}, [query]);

	return html`<input value=${query} onChange=... /> ...`;
}
  • useState = een geheugentje. Verandert het? Dan tekent React het blokje vanzelf opnieuw.
  • useEffect = "doe iets als dit verandert". Hier: zoeken als je typt.
  • We wachten 250 milliseconden na het typen, zodat we niet bij elke letter de server lastigvallen.
  • htm is een klein hulpje waarmee we React-code kunnen schrijven zonder extra programma's (geen "build-stap").
🎤 Zeg dit "De zoekpagina is een React-component. Hij bestaat uit kleinere componenten: SearchPage, UserRow en Avatar. Met useState onthoudt hij de zoekterm en de resultaten, en met useEffect zoekt hij live mee terwijl je typt."

8. De keuken: de backend (OOP)

De backend is geschreven in PHP en is objectgeoriënteerd (OOP). Wat betekent dat?

🧸 Heel simpel: koekjes! Een klasse is een koekjesvorm 🍪. Een object is een koekje dat je met die vorm maakt.
Van één vorm kun je veel koekjes maken. In de code: new PostController() = "maak een koekje met de vorm PostController".

De drie soorten koks

SoortMapWat doen ze? (simpel)
👨‍🍳 Controllerssrc/Controllers/De chef-koks. Ze krijgen de bestelling, controleren of alles klopt en bepalen wat er moet gebeuren. Eén chef per onderdeel (posts, stories, berichten...).
🧊 Repositoriessrc/Repositories/De voorraadbeheerders. Alleen zij mogen in de voorraadkast (database). Ze pakken dingen of zetten dingen terug.
🧰 Coresrc/Core/Het gereedschap van de keuken: de bestelling lezen (Request), het antwoord sturen (Response), wie is er binnen (Session), foto's opbergen (ImageStorage), controleren (Validator).

Overerving: kinderen lijken op hun ouders

🧸 Heel simpel Er is één oma-kok: Controller. Zij weet hoe je netjes werkt: fouten opruimen, kijken wie er ingelogd is.
Alle andere koks zijn haar kleinkinderen: PostController, StoryController, enzovoort. Ze hebben die kunstjes van oma geërfd, dus ze hoeven het niet opnieuw te leren. Dat heet overerving (extends).
abstract class Controller {                   // de oma-kok (je kunt haar zelf niet "bestellen": abstract)
	public function run() { ... }             // werkt netjes, vangt fouten op
	abstract protected function handle();     // "elk kleinkind maakt zijn eigen gerecht"
	protected function currentUser() { ... }  // wie is er ingelogd?
}

class PostController extends Controller {     // kleinkind: erft alles van oma
	protected function handle() { ... }       // zijn eigen gerecht: foto's
}

De vier OOP-woorden die je moet kennen

WoordSimpelWaar in Kiekje?
OverervingKind erft kunstjes van ouder8 controllers erven van Controller, 8 repositories van Repository
AbstractieEen "plan" dat je niet zelf gebruikt, alleen de kinderenabstract class Controller, abstract handle()
EncapsulatieEen doos met een slot: niet iedereen mag erinprivate en protected: alleen de repositories mogen bij de database
PolymorfismeDezelfde vraag, elk kind doet het op zijn eigen manierrun() roept bij elke controller een andere handle() aan

Nog een slim ding: LikeTable. Liken werkt bij foto's, reacties én stories precies hetzelfde. Dus hebben we één klasse gemaakt die we drie keer hergebruiken, in plaats van drie keer dezelfde code te schrijven.

Hoe een deurtje werkt

Een deurtje in backend/api/ is heel klein. Het roept alleen de juiste chef-kok:

require __DIR__ . '/../bootstrap.php';          // zet de keuken aan (laadt alle klassen)
(new Kiekje\Controllers\PostController())->run(); // "chef-kok van de foto's, aan het werk!"
🎤 Zeg dit "De backend is objectgeoriënteerd. Er zijn twee abstracte basisklassen: Controller en Repository. Acht controllers erven van Controller en regelen elk één onderdeel. De repositories doen alle SQL. Zo staat elke taak op één plek, en hergebruik ik code, bijvoorbeeld met LikeTable."

10. Zo gaat het stap voor stap

📷 Een foto plaatsen

  1. Je drukt op Maken (＋) en kiest een foto.
  2. De browser maakt de foto kleiner (max. 1080 pixels), zodat hij snel verstuurd wordt.
  3. Je typt een tekstje en drukt op Plaatsen.
  4. De ober brengt de foto naar posts.php, en de PostController gaat aan het werk.
  5. De chef kijkt: ben je ingelogd? Zo nee: fout 401.
  6. ImageStorage kijkt: is dit echt een foto? (en geen stout programmaatje vermomd als foto). Zo nee: fout 422.
  7. De foto gaat in het fotoalbum (uploads/) met een willekeurige naam.
  8. PostRepository schrijft in de database: "nieuwe foto van jou".
  9. De ober komt terug en je foto staat bovenaan de tijdlijn. 🎉

❤️ Een foto liken

  1. Je tikt op het hartje (of 2× op de foto).
  2. De ober vraagt: "zet een hartje bij foto 12" (interactions.php?action=like).
  3. LikeTable kijkt: stond er al een hartje? Dan gaat het weg. Zo niet, dan komt het erbij.
  4. Het nieuwe aantal hartjes gaat terug en het scherm wordt opnieuw getekend.
  5. Slim: de app stuurt nooit twee hartjes-verzoeken tegelijk. Anders zou de tweede het hartje weer weghalen.

✉️ Een berichtje sturen

  1. Je opent een gesprek. De server markeert de berichten van de ander als gelezen.
  2. Je typt "hoi" en drukt op Enter. De server controleert: ingelogd? bestaat de ontvanger? niet naar jezelf? niet te lang?
  3. Het bericht gaat de database in.
  4. De app van de ander kijkt elke 4 seconden of er iets nieuws is (bij een open gesprek) en elke 15 seconden voor het rode rondje.
  5. Heeft de ander het gelezen? Dan zie jij "Gezien".

🔑 Inloggen

  1. Je typt je naam (of e-mail) en wachtwoord.
  2. De server zoekt jou op en vergelijkt het wachtwoord met de geheime versie (hash) in de database.
  3. Klopt het? Dan krijg je een armbandje (een sessie-cookie), net als in een pretpark. Bij elke vraag laat de browser dat armbandje zien.

15. Vragen die de docent kan stellen

VraagJouw antwoord
Waarom sla je het wachtwoord niet gewoon op?Als de database gestolen wordt, kunnen ze de wachtwoorden niet lezen. Ik sla alleen een hash op (bcrypt) met een salt, zodat twee dezelfde wachtwoorden toch anders zijn.
Wat is SQL-injectie en hoe voorkom je het?Stoute tekst die de database een commando geeft. Ik gebruik prepared statements: de invoer gaat altijd in een apart vakje (?) en wordt nooit uitgevoerd.
Wat is het verschil tussen een klasse en een object?Een klasse is de vorm (bijv. PostController), een object is wat je ermee maakt (new PostController()).
Waar zie je overerving?class PostController extends Controller. Alle 8 controllers erven run() en currentUser() van Controller.
Waarom is Controller abstract?Je gebruikt hem nooit los; hij is een basis. Elke subklasse moet zelf handle() maken.
Wat doet een Repository?Daar staat alle SQL. Zo schrijft een controller zelf geen SQL, en staat alles over de database op één plek.
Waar gebruik je React?De zoekpagina: componenten SearchPage, UserRow, Avatar, met useState en useEffect.
Hoe weet de server wie je bent?Na inloggen krijg je een sessie-cookie. PHP onthoudt bij die sessie jouw gebruikers-id.
Wat gebeurt er als ik andermans foto probeer te verwijderen?De server controleert of de foto van jou is. Zo niet: fout 403 "Dit is niet jouw post."
Hoe test je?9 browsertests met Puppeteer (de hele app) en 23 unit tests met PHPUnit (losse klassen). Ze draaien in een aparte testdatabase.
Waarom hebben meldingen geen tabel?Ze worden afgeleid uit likes, reacties en volgers. Zo kunnen ze nooit verkeerd zijn: haalt iemand zijn like weg, dan verdwijnt de melding ook.
